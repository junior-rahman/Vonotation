# Voitation artwork

Native vector adaptation of the user-supplied “Voitation logo and dictation states.png” concept sheet, v1 (Library libfile_66977d488b508191a82f0529c4ea3a78). Seven rounded voice bars descend into a V. Sand & Cocoa colors remain theme-driven in the interface. Android has an adaptive monochrome icon; both platforms use the same source geometry. Vocading artwork is unchanged.

`logo.svg` is the editable launcher source. UI vectors live in VoitationGlyph/FloatingIcon and DaybookDesign.swift. Accessible labels remain on controls, decorative artwork is hidden from screen readers, and existing reduced-motion behavior is preserved.

Android 0.1.20 uses the selected Quick Thoughts option 01 **Thought Loop** (Library libfile_559965de533c8191a8a3d5f8d5cfb7fc), replacing the earlier folded-note concept. The native open Q, rounded tail and detached upper-right stroke are shared by the idle dot, floating control, recording state, capture sheet, fan heading and saved-text results. Processing symbols follow the Voitation state sheet. No iOS changes are included.

States: V-wave or Thought Loop for ready/pressed/disabled; progress arc for starting; voice bars or Thought Loop with recording dot for listening; dots for finishing/saving/inserting; upload tray; text with progress arc for transcribing; text with sparkle for polishing/converting; check for done/saved/copied; circular arrow for retry/error; slashed microphone for blocked; circled cross for cancelled. Press feedback remains in the control container, disabled artwork is muted, and motion follows Android's animation setting.

A completed clipboard copy caused by a lost dictation input queues the recovery fan. It stays hidden until a later confirmed input activation, and stays hidden for password/PIN fields, locked screens and active recording. Ordinary copies do not queue it. The preview appears once, using the current microphone position and avoiding the active keyboard/caret. Tapping the preview uses the existing guarded paste into the active input; the Clipboard button opens its saved-copy tray. Nothing pastes automatically. It dismisses after 12 seconds or on dismissal/focus loss. Pending previews live in the service session; saved text remains in the existing recovery history and Clipboard archive.

Numeric and phone-number fields automatically request the typing keyboard, like password/PIN/email fields, without changing the saved keyboard preference. Native editor metadata supplies this decision even when the app exposes no editable accessibility node. A deliberate keyboard hide remains local to that input.
