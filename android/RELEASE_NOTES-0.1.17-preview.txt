Backup reliability
- Disconnecting or adopting a different Google account clears the previous account’s saved-backup freshness status. Failed connection changes restore their previous status during rollback.
- Backup freshness checks run outside the interface thread, share cached work and reject results made stale by new dictations, thoughts, draft edits or settings. Unknown freshness is shown as unknown instead of being called an outdated backup.
- Backup controls provide visible schedule/network confirmation, contextual retry or setup actions, and a confirmation before leaving an upload. Back navigation cannot interrupt a confirmed restore/import; Android Home or process termination are separate system events.
- Restore preserves locally available thought source recordings and incomplete offline transcription progress when an archive contains an older or text-only copy of the thought. A restore must not silently replace pending local source work with a completed cloud text snapshot.
- Google and backup failures use neutral descriptions of the observed problem and relevant retry actions. A failed request alone is not presented as proof that the signing certificate, account or OAuth setup is incorrect.

Existing dictation, Quick thoughts and Clipboard behavior is retained. Text backups exclude recordings and clipboard history; locally retained source audio remains on this phone. The broader color and aesthetics refresh follows the reliability work.
